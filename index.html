What is working

Good platform direction

The four-tab information architecture is stable during workouts. Core actions are prominent, the UI has explicit Light/Dark modes, large-text QA layouts, reduced-motion CSS, clear modal exits, and confirmations for destructive actions.

Recommended fix order

  1. Restore Light Mode contrast on the Insights workouts value. White over the pale blue summary surface is approximately 1.1–1.2:1; use the semantic primary label colour or darken the surface to reach at least 4.5:1.
  2. Implement modal focus management. On open, focus the title or first control; make background content inert; trap focus; restore focus to the trigger on close. In SwiftUI, prefer native sheets and alerts.
  3. Remove the whole-app live region. Announce only short, atomic status messages such as “Set recorded” or “Goal saved”.
  4. Expose selected states. Theme, volume grouping, and target zone controls need native Picker/segmented semantics or an accurate selected/pressed accessibility value.
  5. Define the native support matrix. Record minimum iOS, devices, orientations, and locales before implementation.
  6. Raise the “Browse standard splits” target to at least 44 pt.

Detailed findings

F-01 · Native deployment scope is undefined

FailP1INV-001MUST know
ObservationNo minimum iOS version, supported device list, orientation policy, or locale set is present. The repository is explicitly a prototype/handoff source.
RemediationRecord the deployment target, iPhone models/form factors, orientation support, locales, and SwiftUI/UIKit boundaries in the app repository before design sign-off.

Static evidence: README.md:5–52, docs/swiftui-handoff.md:1–60; repository search found no target configuration.

Apple HIG — Layout · Confidence: high

F-02 · Insights workouts value fails Light Mode contrast

FailP1COLOR-003MUST
ObservationThe value “7” is forced to white over a pale blue translucent/gradient surface. The defined endpoints produce roughly 1.1–1.2:1 contrast, far below 4.5:1.
RemediationUse var(--text)/label for the number in Light Mode, or make the active surface dark enough to provide at least 4.5:1. Retest all custom accent choices.

Static: prototype/styles.css:383 and prototype/styles.css:613–624. Runtime: Light Mode computed foreground rgb(255,255,255) on the first summary card.

Apple HIG — Dark Mode · Accessibility · Confidence: high

F-03 · Sheet focus is not moved, contained, or restored

FailP1A11Y-001MUST
ObservationAfter opening Standard splits, focus remained on the background “Browse standard splits” button. All four background tab buttons retained tabIndex=0 while the modal declared aria-modal=true.
RemediationFor the prototype, focus the modal heading/first control, make the app shell inert, trap keyboard focus, close on Escape, and restore focus. In SwiftUI, use native .sheet, alerts, and confirmation dialogs.

Runtime at 375 × 812. Static modal creation: prototype/app.js:581–588.

Apple HIG — Sheets · SwiftUI accessibility fundamentals · Confidence: high

F-04 · The entire app is a polite live region

FailP1A11Y-001MUST
Observation#app has aria-live="polite", and most actions replace its full HTML. Assistive technology may re-announce large portions of each screen after navigation, set logging, or preference changes.
RemediationRemove the live region from the app root. Add a dedicated atomic status region for short confirmations. In SwiftUI, post narrowly scoped accessibility announcements only when needed.

Static: prototype/index.html:13; full rerender behavior in prototype/app.js:565–573.

F-05 · Selected state is missing from several controls

FailP1A11Y-008MUST
ObservationTheme, Volume grouping, and Volume target zone use a visual .selected class without aria-pressed, tab semantics, or an accessible current value. Runtime exposed “Major groups” and “Moderate” as ordinary buttons.
RemediationUse a native segmented Picker in SwiftUI. In the prototype, add correct pressed/selected semantics and keep visible text aligned with the accessible value.

Static: prototype/app.js:226, prototype/app.js:235, prototype/app.js:535. Units and rest timers provide good counterexamples at line 537.

F-07 · Large-text resilience is promising but not true Dynamic Type

PartialP1TYPE-002MUST
ObservationThe prototype has role-based tokens and ?text=large/?text=accessibility layouts. At 375 × 812, Home, Workouts, and live workout had no measured text overflow. These modes do not cover every iOS Dynamic Type category or Bold Text.
RemediationMap roles to semantic SwiftUI text styles; use adaptive stacks and ScaledMetric where appropriate; test every route through accessibility5 plus Bold Text.

Static: prototype/styles.css:918–1225. Runtime: no overflow in sampled routes at the accessibility QA mode.

F-10 · Semantic intent is documented, but the prototype relies on hard-coded colour

PartialP2COLOR-002SHOULD
ObservationSemantic variables exist for system backgrounds and labels, but many components still specify literal RGB/hex and translucent gradients. This increases contrast and appearance regressions.
RemediationTranslate visual roles—not CSS values—into semantic Color assets and Materials with Light/Dark/Increase Contrast variants. Avoid porting web opacity stacks directly to SwiftUI.

Static examples: prototype/styles.css:494–817; semantic handoff intent: docs/design-tokens.md:5–20.
