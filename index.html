Rerun outcome

Six prior prototype issues are resolved

Insights number contrast, base modal focus containment, root live-region scope, primary selection semantics, the standard-split hit target, and landscape composition now pass their tested web checks.

Priority order

  1. Constrain accent usage by semantic role. Orange produced only 2.20:1 for the active tab label in Light Mode.
  2. Repair the exercise picker. Selected rows need state semantics and focus must remain on the activated row or a deliberate next control.
  3. Give every repeated editor control a contextual name. “Increase working sets” is meaningful; six indistinguishable “+ / −” buttons are not.
  4. Observe System appearance changes. The current implementation samples the media query only during a render.
  5. Define native scope. Minimum iOS, devices, orientations, locales, and SwiftUI/UIKit boundaries remain product decisions.
  6. Synchronize dist/. The portable copy still contains the pre-remediation root live region, color, target, and modal behavior.

R-03 · Selectable accent colors can fail contrast and state semantics

FailP1COLOR-003A11Y-008MUST
ObservationOrange #ff8a24 produced 2.20:1 against the Light Mode tab surface when used for the active tab label. The selected swatch is identified only by a visual class/checkmark; it has no pressed or selected state.
RemediationSeparate decorative accent from semantic foreground roles. Derive a contrast-safe foreground per appearance and expose each swatch with aria-pressed in the prototype and a selected Picker value in SwiftUI.

Runtime at 375×812; static palette and swatches at prototype/app.js:536, visual selection at prototype/styles.css:474–475.

R-04 · Exercise picker selection resets focus and lacks state

FailP1A11Y-001A11Y-008MUST
ObservationSelecting Barbell Bench Press added a visual checkmark, but the row exposed neither aria-pressed nor aria-selected. Rerendering the picker moved focus from the activated row back to the “Add Exercise” heading.
RemediationExpose selected state and preserve focus on the activated result, or move it deliberately to the updated Done control with an announcement. Do not reopen/refocus the entire modal for an internal selection update.

Runtime selection test; markup and rerender at prototype/app.js:656–661 and handler at prototype/app.js:753.

R-05 · Repeated editor controls have ambiguous names

FailP1A11Y-002CTRL-005MUST
ObservationThe workout editor exposes six controls named only “+” or “−” for sets, warm-ups, and rest. The set editor repeats three indistinguishable plus/minus pairs. Remove is not associated with its exercise in the accessible name.
RemediationUse contextual labels and values such as “Increase working sets, 3” and “Decrease rest, 90 seconds.” Name removal with the exercise. Prefer native Stepper controls in SwiftUI.

Runtime accessible-name inventory; static at prototype/app.js:343–350 and prototype/app.js:650.

R-13 · System appearance does not update automatically

FailP1COLOR-001MUST
ObservationExplicit Light and Dark choices render correctly. System mode reads prefers-color-scheme only when applyTheme() runs; there is no media-query change listener, so an appearance change can remain stale until another render.
RemediationObserve media-query changes in the prototype. In SwiftUI, store only the explicit override and let the environment drive System appearance.
